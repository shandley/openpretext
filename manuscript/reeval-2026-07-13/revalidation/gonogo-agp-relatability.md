# GO/NO-GO: can pre-curation and curated assemblies be scored for curation concordance without sequence alignment?

Date: 2026-07-13
Question: for the case-study species, can the PRE-curation (scaffolded) and CURATED
(post-curation) assemblies be related to each other well enough to score curation
concordance (contig to chromosome assignment, order, orientation) WITHOUT first
running a sequence alignment? This is a feasibility gate for the end-to-end curation
case study in the reeval paper plan.

## Verdicts (per species, verdict first)

- **King quail, *Coturnix chinensis*, assembly bCotChi1: RELATABLE-BY-ID. GO.**
- **Zebra finch, *Taeniopygia guttata*, assembly bTaeGut1 (curated GCA_003957565.4): NEEDS-ALIGNMENT. NO-GO by ID.**
- **Koala, *Phascolarctos cinereus*, assembly mPhaCin1: RELATABLE-BY-ID. GO (with a caveat, see below).**

## The load-bearing finding (read this first)

Relatability is determined by the **curation-workflow generation, not by the species.**

The modern Sanger / PretextView curation workflow deposits, next to the curated
assembly, an exported AGP whose object column is the curated chromosomes and whose
component column is the **pre-curation scaffold names, with coordinates and
orientation.** That single AGP IS the concordance record. It states, per curated
chromosome, which pre-curation scaffolds compose it, in what order, at what
orientation, and (because coordinates are preserved) where the curator cut a scaffold.
No alignment is needed: the pre-curation scaffold ID is the join key.

The older VGP curation workflow (2018 to 2022 era) deposited only a `chromosomes.csv`,
which renames the curated assembly's own internal scaffold names to chromosome
numbers. It does not reference the pre-curation scaffold names at all, so it does not
bridge pre to post. For those assemblies the pre-to-post relationship lives only inside
the curator's PretextView session, which was not exported as an AGP, and the published
curated assembly (on GenBank) carries GenBank accessions for its components. Relating
those back to the pre-curation scaffolds then requires coordinate or sequence
correspondence, i.e. an alignment.

**One-line reusable discriminator for any GenomeArk species:** does
`assembly_curated/.../pretextmap/*.pretext.*.agp` exist and contain `Painted` component
rows? If yes, RELATABLE-BY-ID (GO). If the curated side has only `chromosomes.csv`,
NEEDS-ALIGNMENT (NO-GO by ID).

## Fact discipline

Every S3 path, NCBI accession, and file below was fetched live during this session
via `aws s3 ls/cp --no-sign-request s3://genomeark/...`, the NCBI Datasets v2 REST API,
and the NCBI genomes FTP tree. AGP content was read from the downloaded files. Items I
did not independently verify are flagged UNVERIFIED inline. Local overview `.pretext`
maps for all three species already exist under `test-data/`
(`Coturnix_chinensis_post.pretext`, `Taeniopygia_guttata_post.pretext`,

## 1. King quail *Coturnix chinensis* bCotChi1: RELATABLE-BY-ID (GO)

### Verified paths

Pre-curation (scaffolded, VGP HiC 2.0 pipeline output, dated 2023-10-03):
- `s3://genomeark/species/Coturnix_chinensis/bCotChi1/assembly_vgp_HiC_2.0/bCotChi1.HiC.hap1.20231003.fasta.gz` (296 MB)
- `s3://genomeark/species/Coturnix_chinensis/bCotChi1/assembly_vgp_HiC_2.0/bCotChi1.HiC.hap2.20231003.fasta.gz` (294 MB)
- Pre-curation SALSA scaffolding AGP (contig to scaffold): `.../assembly_vgp_HiC_2.0/intermediates/hap1/salsa/bCotChi1_bCotChi1_s2.agp` (and the hap2 equivalent under `intermediates/hap2/salsa/`)

Curated (dated 2024-04-23):
- Curated FASTA: `s3://genomeark/species/Coturnix_chinensis/bCotChi1/assembly_curated/bCotChi1.hap1.cur.20240423.fasta.gz` (296 MB) and `bCotChi1.hap2.cur.20240423.fasta.gz`
- **Concordance AGP (PretextView export): `.../assembly_curated/intermediates/pretextmap/bCotChi1.combined.pretext.20240422.agp` (35,780 bytes)**
- Curator edit log and savestate alongside it: `bCotChi1.combined.pretext.20240422.edits` (84,501 bytes), `...savestate`
- Chromosome name maps: `.../assembly_curated/bCotChi1.hap1.cur.20240423.chromosome.csv` and `...hap2...` (final `SUPER_N` to chromosome number)

### Evidence that the pre and curated ends share the component set

Pre-curation FASTA header, verified by a byte-range read of `bCotChi1.HiC.hap1.20231003.fasta.gz`:

```
>scaffold_1
```

Curated concordance AGP (`bCotChi1.combined.pretext.20240422.agp`), representative lines
(object = curated chromosome, component col 6 = pre-curation scaffold):

```
##agp-version   2.1
# DESCRIPTION: Generated by PretextView Version 0.2.5
# HiC MAP RESOLUTION: 59245.052002 bp/texel
Scaffold_1  1        888675     1   W  H1.scaffold_35  1        888675     +  Painted  Hap_1
Scaffold_1  888776   72812268   3   W  H1.scaffold_1   1        71923493   +  Painted
Scaffold_1  72990204 73227183   7   W  H1.scaffold_54  1        236980     -  Painted
Scaffold_1  73405119 185022796  11  W  H1.scaffold_1   71923494 183541171  +  Painted
Scaffold_2  651796   26541883   3   W  H2.scaffold_1   157177123 183067210 -  Painted
```

The component column is `H1.scaffold_N` / `H2.scaffold_N`: the pre-curation hap1/hap2
scaffolds (named `scaffold_N` in the vgp_HiC release FASTA) with an `H1.`/`H2.`
haplotype prefix added when hap1 and hap2 were concatenated into the one combined
pretext map that was curated. Every one of the 513 `W` component rows resolves to a
pre-curation scaffold: 329 `H1.scaffold_N` rows and 184 `H2.scaffold_N` rows, with no
other component type present. Orientation (+/-) and intra-scaffold coordinate ranges
are given, so a scaffold that the curator cut appears as two component rows into the
same `scaffold_N` at complementary coordinate spans (see the two `H1.scaffold_1` rows
above). This directly encodes assignment, order, orientation, and cut points, all
keyed on the pre-curation scaffold ID.

Coordinate cross-check: the curated AGP's largest referenced end for `H1.scaffold_1` is
183,541,171 bp; the pre-curation SALSA-stage `scaffold_1` length is 183,560,827 bp.
These agree to 0.01 percent. The small delta is the difference between the SALSA
intermediate and the vgp_HiC release FASTA (minor post-SALSA gap or edge trimming). For
exact-coordinate scoring, use the release FASTA `bCotChi1.HiC.hap1.20231003.fasta.gz`
(the sequence the combined pretext was actually built on) as the pre-curation reference,
not the SALSA intermediate AGP. The scaffold IDs are identical either way, so
ID-relatability is unaffected.

### Verdict

RELATABLE-BY-ID. Scoring contig-to-chromosome assignment, order, and orientation needs
no alignment: read it straight from `bCotChi1.combined.pretext.20240422.agp`, joining on
`scaffold_N`. This is the strongest de-novo case study candidate: the input was a
freshly scaffolded assembly and the curation was substantive.

## 2. Zebra finch *Taeniopygia guttata* bTaeGut1: NEEDS-ALIGNMENT (NO-GO by ID)

### Verified paths

Pre-curation (VGP standard 1.0, 2018):
- SALSA scaffolding AGP: `s3://genomeark/species/Taeniopygia_guttata/bTaeGut1/assembly_vgp_standard_1.0/intermediates/salsa/scaffolds_FINAL.agp` (object = `scaffold_N`, component = Scaff10x / Super-Scaffold inputs)

Curated on GenomeArk (final release 2021-04-09):
- Curated FASTA: `s3://genomeark/species/Taeniopygia_guttata/bTaeGut1/assembly_curated/bTaeGut1.pri.cur.20210409.fasta.gz`
- `chromosomes.csv` files only: e.g. `bTaeGut1.pri.cur.20181016.chromosomes.csv`, `...20200720.chromosomes.csv`, `...20210409.chromosomes.csv.gz`
- **No AGP anywhere under `assembly_curated/`.** The only curated-side pretext is `assembly_curated/evaluation/pretext/bTaeGut1.pri.pretext`, with no exported AGP, edits, or savestate.

Curated on NCBI (the published assembly, verified via NCBI Datasets):
- `GCA_003957565.4` (assembly name `bTaeGut1.4.pri`). Alt haplotype is `GCA_003957525.2`.
- Chromosome AGP: `.../GCA_003957565.4_bTaeGut1.4.pri_assembly_structure/Primary_Assembly/assembled_chromosomes/AGP/chr1.comp.agp.gz` and per-chromosome siblings.

### Why the IDs do not bridge

Pre-curation SALSA AGP (`scaffolds_FINAL.agp`), representative lines (object = pre-curation
scaffold, component = its inputs):

```
scaffold_193  1      17908587  1  W  Super-Scaffold_43  1  17908587  +
scaffold_192  1      22851     1  W  Scaff10x_618_obj   1  22851     -
scaffold_192  22852  23351     2  N  500  scaffold  yes  na
scaffold_192  23352  46593     3  W  Scaff10x_612_obj   1  23242     +
```

Curated GenomeArk `chromosomes.csv` (this is all the curated side offers, and it does
NOT reference the pre-curation `scaffold_N` names):

```
Superscaffold_1,1,yes
Superscaffold_2,2,yes
Superscaffold_3,3,yes
```

Curated NCBI chromosome AGP (`chr1.comp.agp.gz`), object and component are both GenBank
accessions:

```
CM012081.2  1  114020016  1  O  RRCB02000015.1  1  114020016  +
```

NCBI local-ID maps for this assembly:
- `component_localID2acc`: placed-chromosome component local IDs are the CURATED names
  (`SUPER_31 -> RRCB02000001.1`, `SUPER_27 -> RRCB02000002.1`, ...). The pre-curation
  `scaffold_N` identity is gone for chromosome-assigned sequence.
- `scaffold_localID2acc`: some unplaced pieces DO retain pre-curation lineage
  (`scaffold_104_ctg1 -> RRCB02000041.1`, `scaffold_108_ctg1 -> RRCB02000042.1`, ...),
  so unplaced material is partially trackable by ID with effort.

The chain that matters for scoring, pre-curation `scaffold_N` to curated chromosome, is
broken for the placed (chromosome-assigned) sequence: the curated components are GenBank
accessions whose local IDs are curated `SUPER_N`, not pre-curation `scaffold_N`, and no
published single-ID key joins the two ends. You would have to align the pre-curation
scaffolds to the curated chromosomes to reconstruct the mapping.

### Verdict

NEEDS-ALIGNMENT. This verdict is now verified against both GenomeArk and the NCBI
curated assembly (not inferred from GenomeArk absence alone). A partial, effortful ID
bridge exists for unplaced scaffolds via `scaffold_localID2acc`, but not for the placed
chromosome sequence, which is the part you need to score assignment, order, and
orientation. bTaeGut2 was spot-checked and is the same older-workflow generation
(pre-curation SALSA AGPs present, curated side is `chromosomes.csv` with no exported
AGP). bTaeGut3 through bTaeGut10 have no curated AGP artifacts at all; bTaeGut7 has a
2025 verkko `manual_curation` tree with a `path-to-chr.csv` and a tracks pretext but,
as checked, no exported painted AGP. UNVERIFIED whether any finch assembly anywhere
carries a modern PretextView-export AGP; none was found in this session.

## 3. Koala *Phascolarctos cinereus* mPhaCin1: RELATABLE-BY-ID (GO, with a caveat)

### Verified paths

- **Concordance AGP (PretextView export): `s3://genomeark/species/Phascolarctos_cinereus/mPhaCin1/assembly_curated/intermediates/pretextmap/phaCin.pri.GCA_003287225.2.multimap.20250902.pretext.20250923.agp` (20,731 bytes)** with a `...savestate` sibling.
- Curated FASTA: `.../assembly_curated/mPhaCin1.pri.cur.20250923.fasta.gz` (UNVERIFIED size; listed in prior scoping as ~1.06 GB)
- `chromosomes.csv`: `.../assembly_curated/mPhaCin1.pri.cur.20250923.chromosomes.csv` (SUPER_1..7, SUPER_X)
- The assembly holds no `genomic_data/` and no separate pre-curation scaffolded assembly directory: its input was the already-published GCA_003287225.2.

### Evidence

Curated concordance AGP (`phaCin.pri...pretext.20250923.agp`), representative lines:

```
Scaffold_1  1         185508874  1  W  Scaffold_4.H1   1         185508874  +  Painted
Scaffold_1  185508975 730051568  3  W  Scaffold_4.H1   185801169 730343762  +  Painted
Scaffold_2  1         36731537   1  W  Scaffold_1.H1   258679655 295411191  -  Painted
Scaffold_4  1         682017     1  W  Scaffold_11.H1  1         682017     +  Painted  X
Scaffold_4  682118    1169272    3  W  Scaffold_14.H1  1         487155     -  Painted
```

Same structure as the quail: object = curated chromosome, component = input scaffold
(`Scaffold_N.H1`, the GCA_003287225.2 scaffolds with an `.H1` haplotype tag), with
coordinates and orientation. Relatable by ID with no alignment.

### Caveat (why koala is a GO but not equivalent to the quail)

The koala's input was an already chromosome-level GCA assembly (`Scaffold_N.H1` are
already large chromosome-scale sequences), and this 2025 pass is a re-curation / QC
pass, not de-novo scaffold-to-chromosome assembly. The concordance it lets you score is
QC-of-an-already-curated-assembly (did the re-curation move, cut, or reorient any
chromosome-scale piece), which is a narrower claim than de-novo curation. The quail
carries the de-novo GO weight; the koala confirms the modern-workflow pattern
generalizes and gives a clean second GO example.

## Bottom line for the case study

- GO on scoring curation concordance without alignment, on **quail bCotChi1** (de-novo,
  strongest) and **koala mPhaCin1** (re-curation / QC, cleaner but narrower). Both expose
  a PretextView-export AGP whose components are the pre-curation scaffolds with
  coordinates and orientation, which is exactly the assignment plus order plus
  orientation record needed.
- NO-GO by ID on **finch bTaeGut1**: the older VGP workflow left only a `chromosomes.csv`
  and a curated GenBank assembly with accession-renamed components, so relating pre to
  post needs an alignment. Use the finch only if you are willing to run that alignment,
  or drop it in favor of another modern-workflow specimen.
- Actionable selection rule for finding more GO species on GenomeArk: keep only
  assemblies where `assembly_curated/.../pretextmap/*.pretext.*.agp` exists with
  `Painted` rows. That one check separates GO from NO-GO without downloading sequence.
